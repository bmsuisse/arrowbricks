# IPC replay and NDJSON allocation experiments

These are local changes after 3.1.3, not a published release. Raw timing and
count samples are in [the accompanying JSON](2026-09-06-lowlevel.json).

## Findings

| Measurement | Local 3.1.3 baseline | Candidate | Interpretation |
| --- | ---: | ---: | --- |
| Rust JSON encoding, narrow synthetic batch | 35.67 ms | 31.06 ms | 12.9% less encoding time |
| Rust JSON encoding, wide synthetic batch | 82.78 ms | 67.25 ms | 18.8% less encoding time |
| Local HTTP NDJSON, 100k synthetic rows | 205.60 ms | 190.74 ms | 7.2% less time |
| Local HTTP NDJSON, peak process RSS | 833.48 MiB | 635.55 MiB | 23.7% lower peak |
| Cached real-data IPC, 80 decodes on four threads | 221.00 ms | 65.82 ms | 3.36x replay throughput |
| Cached real-data IPC, 20 decodes on one thread | 54.51 ms | 54.51 ms | Unchanged |
| Live NDJSON, first comparison median | 964.45 ms | 884.85 ms | 8.3% less time |
| Live NDJSON, repeated comparison median | 855.58 ms | 928.48 ms | 8.5% more time |
| Live NDJSON, first comparison peak RSS | 201.67 MiB | 142.50 MiB | 29.3% lower peak |
| Live NDJSON, repeated comparison peak RSS | 216.45 MiB | 139.50 MiB | 35.6% lower peak |
| Compiled extension size | 9,288,784 bytes | 9,288,784 bytes | Unchanged |

The CPU and memory improvements are reproducible on this machine. Live query
latency has **no consistent improvement** across the two comparisons. The
replay speedup is concurrent decoding of cached bytes, not warehouse throughput.
These changes do not reduce persisted cache bytes or wheel size.

## Hypotheses and decisions

1. **Detach cached IPC decoding from Python:** retained. Only the Rust decoding
   phase releases the interpreter; Python object construction remains attached.
   The immutable bytes owner remains alive through decoding and downstream
   Arrow consumers. The new thread-progress regression test fails against the
   released baseline and passes against the candidate.
2. **Eliminate the temporary whole-chunk NDJSON buffer:** retained after iteration.
   A writer collects complete lines and carries incomplete bytes between writes,
   including writes split inside a Unicode character. The first implementation
   used a scalar byte scan and was 7–15% slower; it was rejected. Using `memchr`
   made this path faster. That crate was already transitive, so making it direct
   introduces no new crate version or Python runtime dependency.
3. **Use a Thrift size hint for LZ4 output capacity:** prototyped, then removed
   without a performance claim. A subsequent [allocation experiment](2026-09-06-lz4-capacity.md)
   found that a slightly short hint doubles retained capacity and exact hints
   regress decoding time for several synthetic shapes. The existing
   decompression implementation remains unchanged.

The experiments were informed by [PyO3's performance guidance](https://pyo3.rs/main/performance)
and the [Rust Performance Book](https://nnethercote.github.io/perf-book/introduction.html),
especially [heap allocations](https://nnethercote.github.io/perf-book/heap-allocations.html).
The requested `rust-async-patterns` skill and its supporting instructions were
read. No new async concurrency policy or unsafe code was introduced.

## Method

- macOS arm64, eight CPUs, 16 GiB RAM; Rust 1.93.1, Python 3.14.3.
  Primary comparisons use locally compiled release wheels with the same build
  configuration. Earlier exploratory comparisons against a PyPI wheel are
  excluded because compiler provenance differs.
- Rust encoding: nine alternating A/B and B/A rounds for each shape, discard
  round zero, compare median times. The baseline implementation lives only in
  test code. Exact output equality is checked before timing.
- Synthetic Python benchmarks: four fresh processes in baseline/candidate/
  candidate/baseline order. Replay uses two warmups and seven timed trials per
  thread count; report the median of process medians. NDJSON discards one warmup
  and records four trials per process. Synthetic output hashes matched.
- Live NDJSON: read-only queries against a real warehouse, 10k rows and 120
  columns, Thrift, LZ4 enabled, concurrency explicitly 64. Two persistent worker
  processes, two warmup pairs then eight measured pairs, alternating execution
  order. Every pair matched all row values using an order-independent checksum
  comparison in memory. Checksums, SQL, identifiers and data are not published.
  A separate A/A control using the same baseline in both workers measured
  745.29 versus 772.25 ms, illustrating run-to-run noise.
- Real-data replay: each worker fetches real Arrow data and writes IPC into
  memory only. Decode/re-encode matches the original IPC bytes exactly before
  timing. Four fresh processes in alternating version order, two warmups and
  seven timed trials. Single-thread trials decode 20 times; four-thread trials
  decode 80 times total. This tests the actual cache path with real data without
  persisting it.
- RSS is the operating system's process high-water mark, including Python and
  returned objects; it is not an isolated allocator measurement or cache size.

## Reproduce without warehouse access

Install the repository's test dependencies and unpack each release wheel into
its own directory. Use the same interpreter for both versions:

```bash
PYTHONPATH=/tmp/baseline .venv/bin/python benchmarks/benchmark_lowlevel.py prepare /tmp/synthetic.arrow
PYTHONPATH=/tmp/baseline .venv/bin/python benchmarks/benchmark_lowlevel.py replay /tmp/synthetic.arrow
PYTHONPATH=/tmp/candidate .venv/bin/python benchmarks/benchmark_lowlevel.py replay /tmp/synthetic.arrow
PYTHONPATH=/tmp/baseline .venv/bin/python benchmarks/benchmark_lowlevel.py ndjson /tmp/synthetic.arrow
PYTHONPATH=/tmp/candidate .venv/bin/python benchmarks/benchmark_lowlevel.py ndjson /tmp/synthetic.arrow
CARGO_BUILD_JOBS=1 cargo test --manifest-path rust/arrowbricks_core/Cargo.toml --release --no-default-features --lib benchmark_ndjson_collector -- --ignored --nocapture
```

Repeat with reversed version order. The script generates synthetic data and
does not load warehouse credentials. Warehouse-specific scripts remain private.

## Validation

The selected candidate passed 119 Rust tests, 48 PyO3 tests and 65 Python tests;
two manual Rust benchmarks were ignored and one Python test skipped. Ruff,
type checking, formatting and Clippy passed (with the existing
`clippy::type_complexity` allowance). Coverage includes split UTF-8, large rows,
multiple batches, null/non-finite handling, IPC ownership and concurrent replay.
Both live NDJSON comparisons and the real-data IPC round-trip checks passed.
